# 《瑶瑶如她》OCR 评估结论（2026-09-18）

本文是本轮评估的远端可读摘要。原始帧、逐条 JSON、缓存和音频仍保留在本地 `data/`，该目录默认被 Git 忽略。

## 结论一：短字幕与单字识别

在 7 集、98 条短字幕样本上，推荐使用 RapidOCR PP-OCRv6 small，并采用以下候选与筛选策略：

- 保留全片 1 秒网格作为兜底；真实 ASR segment 前后各扩 500ms，窗口内增加 250ms 采样。
- 使用字幕 ROI `[0.10, 0.44, 0.85, 0.82]`。
- 只保留检测框纵向中心约 `y=0.715–0.815` 的文字框，再拼接识别结果。
- 默认选择距离字幕 cue 中点最近的候选帧。

2026-09-19 在 Win11 RTX 4070 上用完整真实输入重跑后，该方案恢复了 6/6 条历史漏检；1–2 字样本为 40/41 召回且完全匹配，3–4 字样本为 57/57 召回且完全匹配，全部为 97/98，CER 0.0039。共同的 70 个无字幕背景探针误报为 2 帧。该结果仍待人工复核，不能外推为所有片源的绝对零漏检。

## 结论二：边界优化后的默认值

在同一批冻结样本上，推荐方案为：cue 首尾各避开 100ms、使用稳定 OCR 框轨迹、单字至少间隔 100ms 的双帧确认，并保留单帧可见回退。

- 纯 1 字：20/20 召回、20/20 完全、CER 0
- 1–2 字：41/41 召回、41/41 完全、CER 0
- 3–4 字：57/57 召回、57/57 完全、CER 0
- 全部 98 条：98/98 召回、98/98 完全、CER 0
- 空结果：2 → 0；插入背景噪声结果：1 → 0；共同背景探针仍为 2/70

100ms 和 150ms 在准确率上并列，但 100ms 对短 cue 更宽松，因此作为默认值。该结论只适合作为方案 E 的 cue 边界选帧默认配置，不代表全场景 OCR 已解决。

推荐参数：`trim_start_ms=100`、`trim_end_ms=100`、`decode_pts_guard_ms=40`、`min_inner_candidates=3`、`single_char_confirmation_gap_ms=100`，并启用 `single_frame_visible_fallback` 和 `untrimmed_E_fallback`。

## 结论三：模型选择

在 6 集、72 帧短词/语气词样本上：

- PP-OCRv6 small：69/72 完全匹配，代理 CER 0.101，无空结果，综合最稳，作为默认首选。
- PP-OCRv5 mobile：速度最快，但准确率较低，适合快速预览。
- PP-OCRv5 server：代理 CER 略低，但约 10 秒/帧，不适合作为 Windows CPU 默认。
- PP-OCRv6 medium：速度慢且质量没有优于 v6 small，不推荐。

样本中的 16 条目标短字（你、爸、妈、嗯等）在四个模型上均完全识别；源 SRT 没有“哼”，因此“哼”未被验证。

## 结论四：ASR 密集时间窗提高了冻结样本候选覆盖

本机已生成覆盖第 1、16、31、35、39、48、50 集的真实 transcript。在相同 ROI 0.78、原始文字框和中点选择规则下，只改变候选时间表：全片 1 秒网格为 79/98 召回、71/98 完全匹配、CER 0.4134；保留该网格并在 ASR 窗口内增加 250ms 采样后为 97/98 召回、90/98 完全匹配、CER 0.1811，两者背景误报同为 12/70。

因此，ASR 时间窗内的密集采样在这批冻结片源上提高了短字幕候选覆盖。该方案始终保留全片 1 秒兜底网格，所以增加的是准确率和计算量，不能据此声称 ASR 可以减少总候选数。ASR 只用于候选时间窗，未作为 OCR 真值；最终评分使用人工校正 SRT。
